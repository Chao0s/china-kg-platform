## 0. 产品叙事（PR/FAQ 风格）

对于化龙镇中心幼儿园里忙碌的教师而言，教学资源、案例和家长动态散落在各个聊天
群与文件夹中。电子资源平台为幼儿园提供一个可信赖的统一场所——就在教职工和家庭
已经在用的微信里——用来查找并复用课程资源与案例，运行一条清晰的提交 → 审核 → 发布
流程，以五维雷达图评价每名幼儿，并向监护人分享每名幼儿的成长册——成长册在应用内阅读。一个桌面端
PC后台负责处理文件密集型工作与治理工作。家长或教师上传的所有内容在可见之前都要经过强制的
内容安全闸门，未成年人数据按 PIPL 标准处理。

## 1. 问题陈述

幼儿园的教学资源、案例、党建材料、行政文件、教研以及家校沟通分散在多个渠道
（聊天群、纸质、本地文件）中进行。资源难以查找和复用；评价靠人工；家长收到的动态零散；
也没有可审计的记录来追溯哪些内容被分享或下载过。教职工希望有一个可信赖的统一场所，
既能在手机（微信）上使用，又能用桌面后台处理繁重的文档工作。

## 2. 方案概述

**两个原生微信小程序**——教师端（Teacher）与家长端（Parent）——再加一个**专用的 PC后台**
（PC backend），用于文件密集型的上传与治理工作。**本期不做管理端小程序**：管理端角色通过教师端完成
内容管理，并使用 PC后台处理跨班工作。三者共同集中管理八大模块，强制执行审核/发布生命周期，将学期
评价生成为五维雷达图，并为每名幼儿汇编成长册，成长册在应用内阅读。

后端基于**腾讯云**——关系型权威数据源、对象存储、托管媒体处理与 REST API
（[ADR-0014](adr/0014-cloud-vendor-tencent.md)）。所有用户内容在可见之前都要经过强制的内容安全闸门。
实现决策见 §9，架构见 §10。

## 3. 目标与成功指标

### 3.1 目标
1. 一个移动优先的统一场所，承载资源、案例、教研、党建、综合协调以及家园社共育。
2. 一条可靠的提交 → 审核 → 发布生命周期，驳回时附原因并保留历史记录。
3. 面向监护人的轻量、高频家校沟通，且不暴露内部教职工模块。
4. 结构化的幼儿评价（月度与学期），采用五大领域量表与五维雷达图可视化。
5. 面向监护人的每名幼儿成长册，在应用内汇编与阅读。
6. 满足公办幼儿园主体在微信平台上的全部合规要求（内容安全、备案、未成年人数据）。
7. 一份可审计的下载与关键操作记录。

### 3.2 成功指标（目标值待与园方确认；见 [GRILLING.md](GRILLING.md)）
| 指标 | 基线 | v1 目标（首学期） |
|---|---|---|
| 教师周活跃率 | 0 | ≥ 教职工的 80% |
| 家长周活跃率 | 0 | ≥ 监护人的 60% |
| 提交 → 审核中位周转时长 | 人工/未知 | ≤ 24 小时 |
| 已发布的资源/案例 | 0 | ≥ 100 条资源 + ≥ 50 个案例 |
| 完成学期评价的幼儿 | 人工 | 在园幼儿的 100% |
| 在园时光发布节奏 | 临时不定 | 每班约每周 2 次 |
| 成长册定稿率 | 人工 | 每学期在园幼儿的 100% |
| 绕过内容安全的已发布内容 | 不适用 | **0（硬性）** |

## 4. 非目标（v1）
- 小程序内的观察记录——按流程图 04，通过企业微信（WeCom）收集。
- 教研反馈的高级评论/情感分析——后续版本。
- 在线支付、电商或面向公众（未在园）的访问。
- 一个原生（非微信）的独立应用。
- 把多园租户作为一项功能——数据模型保留租户边界，但 v1 仅服务一个园。
- 兴趣/混龄分组——v1 中一名幼儿恰好归属一个班级。
- 按用户的个性化推荐与 LLM 兴趣画像——延后至 v1.x；v1 仅记录知情同意、去除 child_id 的信号。上线时仅面向教师，家长为单独的 v2 决策。见 [ANALYTICS.md](ANALYTICS.md) 乙部 / [ADR-0011](adr/0011-personalization-and-habit-analytics.md)。
- **管理端小程序**——本期不做。管理端角色通过教师端与 PC后台工作。
- 成长册的**任何形式导出**——不出 PDF、不出图片册、不可下载、不可分享、不做服务端渲染。已整体取消，见 §6.6。
- **微信订阅消息。** v1 通知仅在应用内。见 [NOTIFICATIONS.md](NOTIFICATIONS.md)。

## 5. 角色、画像与访问权限

| 角色（Role） | 角色 | 主要职责 | 触达面 |
|---|---|---|---|
| Admin | 管理端 | 审核；发布共建任务；管理内容与用户；配置成长册；查看日志 | 教师端小程序（内容管理）+ **PC后台/CMS** |
| Teacher | 教师端 | 上传资源/案例；完成任务；发布在园时光；填写评价 | 仅小程序 |
| Parent | 家长端 | 查看通知；完成亲子任务；查看在园时光、评价、成长册 | 仅小程序（仅限本人孩子） |

共有**两个小程序**——教师端与家长端——以及**一个 PC后台**。

**访问不变式（服务端强制）：**
- PC后台 / CMS **仅限管理端**；教师与家长无 CMS 访问权限。
- 一名教师**恰好归属一个班级**，由标量班级字段加任课角色承载。原教师-班级关联表已删除；这是产品约束，不只是模式简化。
- 家长端**只**呈现家园社共育内容及其自身的通知/任务；绝不展示教职工模块。
- 身份：一个微信账号（一个 `openid`）可持有多个角色（既是教师又是家长的用户在应用内切换角色）。见 [ADR-0003](adr/0003-client-framework.md)。

## 6. 范围 — 模块规格说明（v1：全部八大模块）

全部八大模块在 v1 中以完整深度交付。“AC”=验收标准（可观察、可测试）。对于
**正确性关键的接缝**（审核生命周期、角色可见性、内容安全、下载记录），AC
以 **EARS** 编写（`当/若/在…期间…系统应当…`），以便直接映射为测试。

### 6.1 首页 (Home)
按角色聚合的待办事项、资源中心通知、常用入口以及推荐课程案例。

用户故事：作为任一角色，我希望有一个按角色定制的首页；作为管理端/教师端/家长端，我希望待办事项只显示我能处理的项；作为任一角色，我希望有指向高频操作的常用入口。

AC：
- [ ] **当**用户打开首页时，**系统应当**只渲染其角色被允许的待办事项与入口。
- [ ] **若**家长请求任何教职工待办事项或教职工模块，**则系统应当**禁止其访问（服务端强制）。
- [ ] 点按推荐课程案例打开案例详情；点按通知打开通知列表，再进入详情。

### 6.2 党建管理 (Party-building management)
党建学习、党建活动与品牌建设。手机端以查看为先；上传通过 PC后台进行。

AC：
- [ ] 每个分类（学习 / 活动 / 品牌建设）都有一个列表，再进入含图片、照片与附件的详情。
- [ ] **在**用户处于移动端期间，**系统应当**以只读方式呈现本模块（上传发生在 PC后台）。

### 6.3 综合协调 (Administrative coordination)
行政统筹、后勤保障与人事文件。手机端以查看为先；PC 端以上传为先。

AC：
- [ ] 三个子区域（行政统筹 / 后勤保障 / 人事管理），各为一个列表再进入详情；文档在手机端预览。
- [ ] 上传发生在 PC后台。

### 6.4 教研培训 (Teaching-research and training)
课程建设、课程库+资源库以及教研研修。v1 优先级：课程
资源、教研资料以及五维雷达图评价。

AC：
- [ ] **当**教师完成五大领域量表时，**系统应当**生成五维雷达图与评估报告。
- [ ] 一个研修详情可承载通知、资料（PPT/PDF/视频链接）与反馈；后端可提取反馈以供后续汇总。

### 6.5 资源库与案例库 （资源库 + 案例库）
两个相互链接的库，支持双向导航。资源按衣/食/住/行/艺分类；案例
按年级 / 五大领域 / 活动形式 / 资源标签筛选。“课程库”是“案例库”的同义词。本模块
承载**审核生命周期**——一处正确性关键的接缝。

用户故事：按分类浏览资源；打开资源详情（简介、解读、获取、转化建议、关联案例）；打开案例详情（简介、详案查看/下载、教师自评、他评、活动反思、关联资源）；以草稿形式上传资源/案例，并被告知是通过还是被驳回及其原因。

AC（EARS）：
- [ ] **当**教师提交一条资源或案例时，**系统应当**将其创建为 `pending-audit` 状态，路由至内容安全闸门（§7），并通知管理端。
- [ ] **在**一个条目尚未通过内容安全期间，**系统不得**使其对任何非作者用户可见。
- [ ] **当**管理端通过一个条目时，**系统应当**将其发布到对应库，并记录一条不可篡改的审核条目（谁/何时/决定）。
- [ ] **若**管理端驳回一个条目，**则系统应当**要求填写原因并保留该审核条目。**驳回为终态：** 条目不退回作者修改，同一条目禁止重新提交，也禁止物理删除以保全审计链；作者应另建新条目。作者撤回同样为终态。
- [ ] **若**已发布的研修记录被就地编辑，**则系统应当**不予执行；已发布记录须以替换方式处理，不得就地修改。
- [ ] **当**一份详案被下载时，**系统应当**记录账号与时间戳（下载记录）。
- [ ] 资源详情链接到相关案例详情，案例详情反向链接回相关资源。

### 6.6 家园社共育 (Home-school-community co-education)
在园时光、亲子任务（含社区教育）、成长档案与成长册。规范
名称依据 [ADR-0002](adr/0002-co-education-naming.md)。

用户故事：教师选择班级/幼儿并发布在园时光（照片/视频/文字）；教师发布带要求与截止时间的亲子任务；家长上传反馈（图片/文字/视频）；教师填写月度与学期评价；管理端配置园所级成长册设置并发布给教师；教师完成班级学期编册并逐名幼儿定稿；监护人在应用内阅读已定稿的成长册。

**成长册仅在应用内。** 不出 PDF、不出图片册、不可下载、不可分享、不做服务端渲染。此项取代早期草稿中的导出模型。

AC：
- [ ] **当**教师为某个班级/幼儿发布一条在园时光时，**系统应当**使其仅对该幼儿的监护人可见（经内容安全后）。
- [ ] **当**一次学期评价完成时，**系统应当**产出五维雷达图与评估报告。
- [ ] **当**管理端发布园所成长册设置时，**系统应当**将封面、Logo、园所介绍、园所栏目与六个年级-季节版式槽位一并冻结为一个不可变发布版本，此后教师方可取用模板。
- [ ] **在**园所设置尚未发布期间，**系统不得**允许任何幼儿的成长册定稿。
- [ ] **当**教师锁定班级学期编册时，**系统应当**将该锁定视为单向，且为该班任一幼儿定稿的前置条件。
- [ ] **当**一名幼儿的成长册定稿时，**系统应当**将其绑定到当次发布版本，标记为永久只读，并在应用内通知每一位有效监护人。
- [ ] **若**一本成长册将超过 200 页，**则系统应当**阻止定稿，而非截断内容。
- [ ] 预检、教师预览、定稿复核与家长查看**应当**调用同一套排版器，任何一端都不得自行估算页数。
- [ ] **若**某个家庭未提交所需内容，**则系统应当**仅向教师提供提醒家长的操作。教师不得代传、接管或更正。

### 6.7 家长端 (Parent client)
刻意保持简洁。通知、亲子任务、在园时光、成长档案、成长册——仅限
监护人本人孩子。

AC：
- [ ] **若**家长端试图渲染任何教职工模块，**则系统应当**予以阻止（该端从不引用教职工模块；可见性由服务端强制）。
- [ ] **当**家长提交任务反馈时，**系统应当**将其经过内容安全，并让教师看到完成情况。

### 6.8 PC后台 (PC backend)
用户管理、内容管理、审核管理、共建任务管理以及数据记录。

AC：
- [ ] **若**非管理员对 PC后台进行认证，**则系统应当**禁止其访问。
- [ ] 权限分配将一个用户映射到管理端/教师端/家长端（一个用户可持有多个角色）。
- [ ] 审核队列为每次决定记录谁/何时/为何；被标记的内容（§7）进入人工复核队列。
- [ ] 名单导入、手动录入、搜索（幼儿园/教师/班级/家长）、通知、模块资料、带进度的共建任务，以及数据记录（下载记录、可选浏览记录、反馈提取）。
- [ ] **园所成长册设置。** 管理端配置封面、Logo、园所介绍、学期寄语与园所自建栏目，并为六个固定的年级-季节槽位（三个年级 × 春秋两季）各指定一套已发布的版式包。发布即分发给教师；仅当本学期尚无班级锁定编册时，方可撤回。
- [ ] **幼儿信息更正。** 监护人提交对幼儿姓名、出生日期或性别的更正申请；管理端与现有记录并排比对，若期间官方记录已变更则给出提示，并通过或附原因驳回。同一名幼儿同时最多一笔待审更正。
- [ ] **当**没有进行中的学期时，**系统不得**允许成长册的发布与撤回，而不是自行推断学期。

## 7. 横切需求

1. **认证与身份。** `wx.login → code2session`（在我方 API 实现）产出 `openid`，绑定到一条名单记录与一个或多个角色。需要时为家长进行手机号授权。引导流程：PRD 同时给出两种方案（名单导入 + 邀请码；以及自助注册 + 审核）——由园长决定（[GRILLING.md](GRILLING.md)）。
2. **内容安全 (Content moderation)。** 在每条用户内容发布前的强制闸门——§8、[ADR-0005](adr/0005-mandatory-content-moderation.md)。
   - **在**一条 UGC 条目尚未通过 `security.msgSecCheck`（文本）/ `security.mediaCheckAsync`（媒体）期间，**系统应当**使其保持 `pending` 状态且对非作者不可见。
   - **若**机器校验失败，**则系统应当**将该条目放入管理端人工复核队列（通过/带原因覆盖）。
3. **通知。** v1 通知**仅在应用内**；v1 全程不发送微信订阅消息。应用内条目本身即通知，而非兜底，并驱动待办事项角标。见 [NOTIFICATIONS.md](NOTIFICATIONS.md)。
4. **媒体管线。** 图片：原生 `wx.compressImage`（轻量、对设备友好）。视频：客户端最小压缩，服务端托管转码。文件存于 **COS 对象存储**，关系型数据库仅保存元数据与对象键。上传支持断点续传/分片，带重试、进度以及可选的仅 Wi-Fi 模式；`pending → uploaded → moderated → published` 的状态可防止连接中断，并由生命周期规则在 7 天后清理未完成的分片。**媒体不经过 API 实例**——客户端凭短时预签名凭证直连 COS 读写，因为实例上行仅 5 Mbps。见 [ADR-0014](adr/0014-cloud-vendor-tencent.md)。
5. **搜索。** PC后台跨幼儿园 / 教师 / 班级 / 家长搜索；各模块按其库进行筛选。
6. **审计与日志。** 必须有下载记录（账号 + 时间）；浏览记录可选；审核决定不可篡改地保留。
7. **国际化。** 简体中文是产品语言；仓库文档为双语。

进行中。由于小程序备案按 AppID 办理，**两个小程序意味着微信侧全部翻倍**：两次备案、两次微信认证、
两次审核提交，且每一次都可能被驳回。

### 8.1 需求
1. **内容安全** — 对所有 UGC（文本/图片/视频/音频/昵称/头像/评论）执行 `security.msgSecCheck` / `security.mediaCheckAsync`；未通过即保持待定；对误报进行人工复核。
2. **小程序备案 (ICP filing)** — 公开上线前强制（自 2023-09-01 起）；管局审核 1–20 个工作日。按 AppID 办理，故**×2**。API 域名的 ICP 备案另行进行中。
3. **微信认证 (WeChat verification)** — 主体认证（¥300/年），**×2**。
4. **教育类目 / 资质** — 类目可能需要办学许可证；提交前匹配相应资质。
5. **未成年人数据 (Minors' data)** — 监护人明示同意、隐私弹窗、数据最小化、严格访问控制、明确留存期（[ADR-0009](adr/0009-minors-data-retention.md)）。PIPL + 未成年人网络保护条例。

### 8.2 合规可追溯性
| 需求 | 控制措施 | 验证方式 |
|---|---|---|
| 没有已发布内容绕过内容安全 | 服务端闸门；客户端不能直接发布 UGC | `harness/code-review.mjs` + 结构评审（ugcWrite 不变式）+ §6.5/§7 的 AC 测试 |

## 9. 实现决策（见各 ADR）

- **客户端 = 原生小程序 + 专用 PC后台**（Element Plus / Ant Design Pro）。[ADR-0003](adr/0003-client-framework.md)。
- **后端 = 腾讯云** — 轻量应用服务器、自建 PostgreSQL 16、COS 对象存储、CI/VOD 媒体处理、DNSPod，以及运行于已备案 HTTPS 域名之下的 REST API。[ADR-0014](adr/0014-cloud-vendor-tencent.md) 在云厂商与媒体存储两处取代 [ADR-0004](adr/0004-backend-cloudbase-vs-alibaba.md)；ADR-0004 关于关系型优于文档型的论证仍然成立。
- **内容安全 = 微信 `security.*`**（强制）+ 可选的第二层商业方案。[ADR-0005](adr/0005-mandatory-content-moderation.md)。
- **渲染 = 在有帮助处采用 Skyline / 默认 WebView；动画从简**；Web DOM 动画库（GSAP、Framer Motion）与小程序不兼容，仅限于 PC后台。[ADR-0007](adr/0007-render-engine-and-animation.md)。
- **工具链 = Node 钩子 + Python 评审。** [ADR-0006](adr/0006-harness-language.md)。
- **五维雷达图** = ec-canvas / ECharts。**成长册** = 在应用内汇编与阅读，无导出，无服务端渲染。
- **API 契约尚不存在。** 四个仓库中均无 OpenAPI 文档、无端点清单，也无动词、路径、载荷、状态码与分页约定。现有的只是字段级绑定契约：832 条绑定覆盖 719 列，它只回答某个输入框写入哪一列，不涉及传输层。设计该契约是当前的关键路径，且为必交付项。

## 10. 架构与数据模型

### 10.1 架构
- **客户端：** 两个原生小程序（教师端、家长端）· 一个 PC后台（Element Plus / Ant Design Pro）。
- **腾讯云：** 位于广州的轻量应用服务器，运行 REST API 与仅监听回环的 **PostgreSQL 16**，作为关系型权威数据源 · **COS** 对象存储承载全部文件，私有读写并开启服务端加密 · 需要时以 CI/VOD 处理媒体 · DNSPod · 已备案 HTTPS 域名，实现 `code2session`。
- **流量形态：** 实例上行仅 5 Mbps，故其只提供 JSON 与预签名凭证；媒体由客户端直连 COS 收发。实例与 COS 之间走同地域内网，不占用实例流量额度。
- **微信平台服务：** `security.*` 内容安全与 `wx.openDocument`。v1 不使用订阅消息。

### 10.2 数据模型（高层）
**字段级模型不在本文档维护。** 它已经落地：**62 张表、719 列**，定义于
`../hualong-backend/db/01_schema.sql`，并已在 PostgreSQL 16.14 上连同种子与校验脚本一并执行通过。
该文件为唯一权威；在此重复一份字段清单，正是上一版失效的原因。指针与更正清单见
[DATA-DICTIONARY.md](DATA-DICTIONARY.md)。

仅供定位的整体形态：单租户的一所幼儿园，含班级与幼儿（**一名幼儿恰好归属一个班级，一名教师亦恰好
归属一个班级**）；监护关系记录在幼儿档案上而非关联表；角色绑定将一个账号映射到一个或多个角色；资源库
与案例库及其提交与不可篡改的审核记录；指向对象存储的文件引用，并携带内容安全状态；通知、共建任务、
在园时光、亲子任务与反馈；月度与学期评价，驱动五维雷达图；成长册约十张表，涵盖园所发布快照、按学期
的班级编册、栏目、组件、素材与逐名幼儿的成长册；仅追加的下载记录；同意与留存记录；以及园历，现已被
三项管理端操作硬性依赖。

## 11. 测试决策

- **什么样的测试是好测试：** 断言可观察的行为（家长看不到教职工模块；被驳回的提交带原因退回；未经内容安全的内容绝不可见），而非实现细节。
- **EARS AC → 测试：** §6.5/§6.7/§7 的 EARS 语句成为最先实现的自动化测试。
- **最先测试：** 审核/发布生命周期、角色可见性以及内容安全闸门。
- **工具链闸门：** 每次变更在提交获准前都运行 `node harness/gate.mjs`（术语、文风、设计/措辞/结构评审、parity、测试）；CI 重复执行。`harness/code-review.mjs` 会标记任何缺少内容安全调用的 UGC 写入路径。
- **E2E：** 文档站点、未来的 H5/PC后台以及知识图谱看板用 chrome-devtools 进行冒烟测试（`tests/e2e/`）——无控制台报错、链接可解析、无障碍通过、CJK 正常渲染。

## 12. 非功能需求
- **性能与体积：** 主包 ≤ 2MB，总计 ≤ 约 30MB；采用分包；媒体存于 COS，绝不打入包体；繁重页面懒加载。
- **弱网韧性：** 断点续传、重试、可容忍离线的草稿（面向中国乡村网络与低端设备）。
- **无障碍：** 面向年长监护人的易读 CJK 字号；触控目标 ≥ 44×44；AA 对比度；绝不仅以颜色传达状态。
- **隐私/安全：** 对未成年人数据采用最小权限访问；密钥绝不进入客户端或仓库；仅 HTTPS；使用已备案的域名。

## 14. 风险与待决问题
- **API 契约尚不存在。** 工程侧最高优先级风险。三个客户端、313 个写入控件背后没有任何端点定义，而这些定义恰好落在单向状态机所在之处。缺此则客户端工作无法启动。
- **时间线。** 主体阻塞已解除，但它自 2026-06-18 悬置至 2026-08-11，合规链条在其后无法启动。在零应用代码、仅余 13 天的情况下，公开上线不会在既定日期发生，由试点承接。
- **美术缺位。** 12 套成长册版式包已发布 0 套。这是外部前置周期最长的一项，且阻塞产品的核心。
- **未成年人数据责任：** 不当处理幼儿媒体是一项法律风险——同意、最小化、留存已在设计中纳入（[ADR-0009](adr/0009-minors-data-retention.md)）。另有两项**尚未签署**：监护人同意与留存期数值，以及开发方的受托处理协议。
- **媒体成本：** **主导成本的是出流量而非存储。** 1 TB 标准存储额度可覆盖前六个月；家长每查看一张照片都计一次外网下行。CDN 是主要手段，但须等备案通过。
- **园历无人负责。** 无进行中学期时三项管理端操作会返回 409 而不执行，而目前没有任何管理界面维护园历。
- **七项阻塞级缺口** 记录在后端缺口册中：登录身份无落点；缺少内容安全状态位；集体照肖像同意；同意与留存数值未签署；手机号可空且不唯一；未成年人同意规则；受托处理协议未签署。
- **一项刻意保留的内容安全问题。** 园所成长册发布路径不调用微信校验，以管理员自身预览作为把关，而管理员上传的照片会进入每一名幼儿的成长册。§8.1 对 UGC 的定义是穷举且宽泛的，§3.2 将绕过量设为硬性 0。此事须在记录上作出决定，本文档不予决定。
- **所有待决问题**都在 [GRILLING.md](GRILLING.md) 中追踪。
